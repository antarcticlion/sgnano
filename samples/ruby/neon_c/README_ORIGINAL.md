# NEON CIRCUIT — ポリゴン版（2026-10-16）

ワイヤーフレーム版（Open Road）と同じカメラワーク・道・街・2 台のレーサーを、**塗りつぶしの三角形**（`fill_triangle`）で描くように作り変えたもの。
タイトルなどのカード・HUD・数字・夕日は、起動時に FB の空きページ（2 と 3）へ一度だけ描いておき、毎フレーム **`blit`** で重ねる。

## ファイル
- `sgnano_megademo_neon_circuit_polygon.rb` — 再生プログラム（mruby 版のファームが要る: `fill_triangle`・`blit` は 2026-10-16 から）
- `NEON_CIRCUIT_POLY.DAT` — 前もって計算したフレーム（この名前のまま、.rb と同じフォルダに置く）
- `generate_neon_circuit_polygon.py` — PC で DAT を作る（Python 3 + NumPy、`--preview` には Pillow）
- `NEON_CIRCUIT_POLYGON_PREVIEW.png` — 生成器の見本（6 フレーム）

ファイラーで .rb を Enter。ログは同じフォルダの `NEON_POLY.LOG`（5 秒ごとに `render_ms`・`worst_ms`・飛ばしたフレーム数）。

## しくみ
- 生成器: 面ごとに裏向きを省き、手前の面（near）で切り、画面の枠で切ってから三角形に分ける。光（1 方向）と距離の霧で色を付け、160 色のパレットにまとめる。
  ホストの z バッファ（半分の解像度）で、隠れて見えない三角形を捨てる。残りを遠い順（画家のアルゴリズム）に並べ、ネオンの辺（隠れた所を除いた線）を上に載せる
- 1 フレームの上限は三角形 170・線 72。実機の速さの見積もり（mode 2 で測った値から）は平均 237ms・最大 283ms（4fps の 250ms を少し越えるフレームは飛ばす）
- 再生: 空はグラデーションの帯（`fill_rect`）、夕日は `blit`（透明色つき）、地面、三角形、線、HUD（パネルを `blit`、時計と区間名は数字・文字の絵を `blit` で並べる）、カード（`blit`）
- DAT（little-endian）: `"NCP1"`、u16 フレーム数、u8 fps、u8 予備、u16 パレット数、パレット（r, g, b）、フレームごとの u32 位置、
  フレームは s16 で 三角形の数・線の数・地平線の y・太陽の x、三角形ごとに x0 y0 x1 y1 x2 y2 色、線ごとに x0 y0 x1 y1 色

## 確かめたこと
- ホストの mruby（実機と同じ処理系・同じ描画の部品）で最後まで走り、1.5 秒・3.5 秒・20 秒・38 秒・50 秒の絵が正しい（タイトル・カウントダウン・夕日・HUD・ゴールのカード）
