# NEON CIRCUIT（ポリゴン版）— sgnano の mruby 見本

2026-11-02 に実機の `B:/NEON_C` から取り込んだ、ChatGPT が作った sgnano 初期向けの
mruby デモを、いまのファーム（mruby 4.0・CLUT8・M33BEATOS）で滑らかに動くように
直したものです。

## いまの環境向けの変更（2026-11-02）

元の版は画面モード 2（RGB555、1 画素 2 バイト）で、5 秒ごとに同じフォルダの
`NEON_POLY.LOG` へ書き込んでいました。実機では次の 2 つが効いて、4 fps の再生が
さらにカクついていました。

- **ログの書き込み**: `File.open(..., "a")` のたびに exFAT/FAT の書き込みが走り、
  1 回およそ **120 ms** 画面が止まっていました（実測: `[fatwr] ... in 119 ms`）。
  再生中はファイルを書かず、進み具合は `puts`（UART のログと画面の端末）に
  出します。書き込みは終了時もしません。
- **RGB555 の描画**: 1 フレーム約 **200 ms**（実測 164〜334 ms）で、4 fps の
  250 ms 予算にぎりぎりでした。**CLUT8（画面モード 3、1 画素 1 バイト）** に変え、
  パックの 161/163 色をパレット 0〜191 に、UI の固定色を 192〜211 に、
  透明色を 255 に置きました。1 フレーム約 **80〜117 ms** になり、8 fps の
  125 ms 予算に収まります。

あわせて次を足しました。

- **8 fps パック**を同じ生成器で作り、既定で使う（`--fps 8 --duration 50`）。
  8 fps が無ければ修正版の 4 fps パックで動く。
- **`q` / ESC で終了**。終了時はファームが元の画面モード・ページへ戻す。
- 終わりに `Machine.video_info` の `underrun` / `fifo_stall` / `recover` /
  `pair_max` を UART へ出す。

### 2026-11-02 の微調整

- **カードの文字を中央に**: タイトルの `NEON CIRCUIT` / `POLYGON RACE`、
  ゴールの `RACE COMPLETE` / `CHECKERED FLAG`、`GRID READY`、
  `MEGACITY HIGHWAY GRAND PRIX` を、それぞれのカードの中央に置いた。
- **車の入れ替えを滑らかに**: 元の台本は 10 秒・25 秒・36 秒で車の位置が
  飛んでいた（特に 10 秒で左右が入れ替わっていた）。キーを打って
  smoothstep でつなぎ、10〜14 秒と 25〜29 秒でゆっくり車線を移るようにした。
  z も飛ばないので、大きさも急に変わらない。
- **ビルを画面外へ出してから消す**: `add_city` の巻き戻しの手前を
  `105 -> -120` にした（ガントリーも同じ）。カメラの後ろへ完全に回ってから
  遠くへ戻るので、画面の端でいきなり消えない。奥側は 1830 ごろまで残す。

## 描画命令の強化版と SGX 版（2026-11-15）

FB のプリミティブ描画（ABI 5.3、2026-11-13）で描き直した。

- **カード**（タイトル・GRID READY・ゴール）: 角丸のネオンの枠（太く暗いペンの上に
  細く明るい線）、楕円の輪、ROM フォントの太字の見出し（光と黒の縁、`TA_CENTER` で中央）。
  5x7 の点の字の表はやめた。
- **夕日**: 色の帯ごとに切り抜き（`clip`）を替えて円を塗る。アトラスの置き場が
  ページの幅からはみ出して右の 8 画素が欠けていたのも直した（太陽・HUD の枠は
  カードの下、y 384〜へ）。
- **HUD**: 角丸の枠、時計と区間名は毎フレーム `text_out`、左下に速度計（`angle_arc`）。
- **ネオンの線**は 2 画素の太さ。

一度だけ描くアトラスでは太いペン・角丸・楕円・文字をそのまま使い、毎フレームは安い
命令だけにした。実機の 1 回の値段（Ruby から、モード 3）:

| 命令 | 時間 |
|---|---:|
| 1 画素の線 `fb.line` | 0.10 ms |
| 1 画素の線を 2 本並べる | 0.18 ms |
| 2 画素のペンの線 `pen(c, 2)` + `move_to` / `line_to` | 1.29 ms |
| 幅 1 の弧 `angle_arc`（150 度） | 0.27 ms |
| 幅 5 の弧 | 3.82 ms |
| `text_out`（太字 16、11 字） | 0.61 ms |
| 透明色つきの `blit` 516x190 | 42.4 ms |

はじめは毎フレームの線を 2 画素のペンで描いて 1 フレーム 162 ms（線だけで 63 ms）に
なったので、線は 1 画素の線を 2 本並べ、速度計の弧は幅 1 を 3 本重ね、カードは四角い
黒の板にして透明色なしで写す形にした。

**生成器の直し**（ユーザー指摘）:

- **高架の橋脚**（紫の柱）がカメラから同じ距離に固定で置かれていて、車について
  来るように見えた。ビル・ガントリーと同じく道の進み（`scroll`）で流す。
- **道路の破線**は固定の位置で 3 フレームごとに点滅していた。破線を `scroll` で
  ずらして流す。

8 fps・4 fps のパックとも作り直した（165 色・163 色）。

| 版（31 kHz・モード 3、B:/NEON_C） | 50 秒で出したフレーム | 1 フレームの平均 | 最悪 | 内訳（読む / 場面 / HUD・カード・切り替え） |
|---|---:|---:|---:|---|
| `neon_c.rb` | 393 / 400 | 106 ms | 181 ms | 13 / 53 / 38 ms |
| `neon_c.sgx` | 398 / 400 | 80 ms | 150 ms | 4 / 39 / 35 ms |

どちらも underrun 0・recover 0。終わりに `NEON [SPLIT]` で内訳を UART へ出す。
ホストの実行器では `$NC_STOP = ミリ秒` を立ててから `load "neon_c.rb"` すると、その時刻で
止めて表示ページを `RBM_PPM` に書き出せる（絵の確かめ用）。

## 実機の測り（2026-11-02、B:/NEON_C、31 kHz / モード 3）

| パック | 50 秒で出したフレーム | 飛ばした | 1 フレームの描画 | 最悪 | 表示の乱れ |
|---|---:|---:|---:|---:|---|
| 8 fps（400 フレーム） | 394（7.9 fps） | 6（最初の 5 秒だけ） | 81〜117 ms | 167 ms | underrun 0・recover 0・fifo_stall 増えず |
| 4 fps（200 フレーム） | 200（4.0 fps） | 0 | 81〜115 ms | 165 ms | 同上 |

`q` / ESC で止めたときも、次のフレームでファイラーへ戻ります。

## 作り直す

```sh
cd samples/ruby/neon_c
python3 generate_neon_circuit_polygon.py --fps 8 --duration 50 -o NEON_CIRCUIT_POLY_8.DAT
```

パックのパレットは **192 色まで**（`neon_c.rb` の `UI_BASE`）。それを越えると
`the pack has N colours` で止まります。生成器の `est_ms` は RGB555 のときの
目安なので、いまの CLUT8 ではもう少し速く出ます。
