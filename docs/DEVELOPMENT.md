## 1. ハードウェア

- **CPU**: WeAct Studio RP2350B Core Board（Cortex-M33 x2、302.4MHz、1.30V）
- **SRAM**: 520KB
- **PSRAM**: 8MB（QSPI、CS = GP0、既定 151.2MHz。定格 133MHz 超）。**推奨品は ESP-PSRAM64H**（64Mbit = 8MB）。
- **フラッシュ**: 16MB
  - 前半 8MB: ファームウェア
  - `0x800000` から 4MB: システムのドライブ S:
  - `0xC00000` から 4MB: フォント ROM（EmbFont16）
- **映像**: R・G・B 各 5 ビットの R-2R ラダー DAC、HSYNC / VSYNC
- **音**: PT8211 x4（1 チップ = 1 声）
- **USB**: ホスト（フルスピード）。デバイス機能は無い
- **C ボード**: GP34〜41 が GPIO A0〜A7（**A6/A7 = GP40/41 は ADC としても使える**）、GP42/43 が DIN MIDI、GP46/47 が ADC L/R
- **時計**: ハードの RTC は無い。NTP で合わせる

## 2. 実行の形

### 2.1 2 つのコア

- **core0 = ベアメタル**。表示のライン割り込み、描画のループ、音の DMA を受け持つ。
- **core1 = M33BEATOS**（自作の RTOS）。アプリ・USB・LAN・言語・SGX・シェルなどのタスクが動く。
- 表示のための資源（パレット・ローレゾのレジスタ・テキスト面）を書き換えてよいのは
  **アプリ時間**（表示のブランキングの窓）だけ。31kHz で 1 フレームに約 1.47ms。
- PSRAM への書き込みも、FB を表示しているときはアプリ時間だけ。書き込み量の目安は 1 フレーム約 60KB。

### 2.2 表示

- PIO0 の SM0 が HSYNC、SM1 が RGB を出す。ライン割り込みは core0。
- DMA がライン表を読み、PSRAM の FB から SRAM のリングへ写し、SM1 へ流す。
- 画面モードは 0〜7:
  - 0: 表示なし
  - 1: テキスト
  - 2 / 3 / 4: テキスト + RGB555 / + ローレゾ + CLUT8 / + CLUT4
  - 5: テキスト + ローレゾ
  - 6: ローレゾのみ
  - 7: テキスト（25 行）+ 320x200x8 のビットマップ
- タイミングは 31kHz / 24kHz / 15kHz の 12 通り。15kHz ではモード 1〜5・7 を開けない。
- テキスト面は 80x30（24kHz では 80x25）。属性は 32 ビット（色反転・ブリンク・線・ボールド・回転・倍角）。
- ローレゾ面は 320x240、BG 2 面 + オブジェクト 128 個。マップは 16 ビット（タイル 10・反転 2・パレット 4）。

### 2.3 音

- PT8211 を 4 声で使う。1 チップ = 1 声、PIO の 1 SM と DMA 1ch。
- 波形は 32 サンプルのステレオ。音程は PIO の分周、音量・音色は事前計算した表。
- 発音マネージャ（core0 の 2kHz の割り込み）とシーケンサー（core1 のタスク）。
- MP3 / OGG / WAV は音楽の口（1 つのステレオ出力）。**VGM / VGZ は全チップの出力を 1 つのステレオ出力（1 DAC / 1 I2S）に混ぜる**（2026-11-10）。`music_info.voices` は 1、`music_voice_chip(0)` に全チップのビットが入る。外部 `vgmplay.sgx` の `-local` だけはアプリ内で 4 ポートのまま。SMF / SGT のシーケンサーもある。
- 音源の 4 声のうち、音楽の口は 1 つのポート（PT8211 1 チップ）を使う。VGM のチップ数が増えても、出力はその 1 本に混ぜる。

### 2.4 ストレージと USB

- **S:** は内蔵フラッシュの 4MB を使う FAT12（4KB クラスタ）。設定と共通のファイルを置く。
- USB ホストは TinyUSB。キーボード・マウス・パッド・タブレット・USB メモリ・HDD・FDD・CD・LAN・MIDI。
- FAT12/16/32・exFAT・NTFS の読み書き、ISO9660 の読み出し。
- USB のエンドポイントは 15 本（ハード上限）。ハブは 4 台まで。

## 4. 決まりごと

- **熱い経路を SRAM に置く。** ライン割り込み・描画・USB の完了の受け口は `__not_in_flash_func`。
  フラッシュ上の関数・定数を呼ばない・読まない。ビルドのたびに `check_sram_funcs.py` が確かめる。
- **PSRAM を USB の受け場にしない。** 呼び手の置き場が PSRAM なら、SRAM の受け場で区切って写す。
- **待ちには必ず上限を付ける。** 表示経路の FIFO 待ちなどで止まったことがある。
- **共有の受け口（usbfat・isofs）は、最初に塞がりを確かめてから受け取ったものを書く。**
- **割り込みの中で長い仕事をしない。** core1 の手伝いが描けなくなり、underrun が出る。
- **PSRAM のスタック・作業場はキャッシュの窓（`0x11...`）を使う。** 取ったら行を捨て、返すときに書き戻す。
- **`printf` の固定の文字列は ASCII のみ。** コメントは日本語でよい。
- **用語**: 割り込みは「発報」、処理の中断は「停止」「計画停止」。「kill」は使わない。

## 5. ビルドと試験（ソース公開後）

```sh
scripts/build.sh                 # build/sgnano.elf / sgnano.uf2
scripts/test_all.sh              # ホスト試験
scripts/flash_swd.sh             # SWD で書き込み
scripts/flash_chunks.sh          # 一括消去が止まるとき
scripts/console.sh               # UART のログとキー
python3 scripts/test_launch.py   # 実機の起動試験
```

- pico-sdk 2.2.0、arm-none-eabi-gcc 10.3.1、CMake + Ninja。
- mruby は `tools/mruby/build.sh` で取得・ビルドする（15〜20 分）。
- 実機の書き込みは BOOTSEL の UF2 か SWD。SWD のときは両コアの C_DEBUGEN を下ろす。
- ホスト試験は 44 本。実機の起動試験は 90/92（既知の失敗は `KNOWN_LIMITATIONS.md`）。

## 6. 用語

| 言葉 | 意味 |
|---|---|
| アプリ時間 | 表示のブランキングのあいだ、アプリが表示の資源を書き換えてよい窓。31kHz で約 1.47ms |
| 受け場 | DMA や USB の転送の受け取りに使う一時の置き場 |
| 発報 | 割り込みが起きること |
| 停止 | 処理を止めること（計画停止を含む） |
| ローレゾ面 | 320x240 の BG 2 面 + オブジェクト 128 個の面 |
| S: | 内蔵フラッシュの 4MB を使うシステムのドライブ |
| SGX | C で組む外部実行ファイル（`.sgx`）。ファームの ABI から機能を使う |
| M33BEATOS | core1 で動く自作の RTOS |
| Zack | 4 声のウェーブテーブル音源 |
