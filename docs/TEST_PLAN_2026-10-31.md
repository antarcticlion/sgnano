# 試験の計画（2026-10-31）

RTOS（関所・QMI の印・シグナル）、表示（取得の待たせ・リング）、メモリの割り振り、ローレゾのマップ（ABI 3.0）を変えたので、
「ホストで毎回回すもの」から「実機で長く回すもの」まで 4 段に分け、自動で回せる形を基本にする。実施は時間がかかるので、ほかのエンハンスと並べて進める（ユーザー判断）。

## 1. 今日変わったもの（試験の的）

| 区分 | 変更 | 壊れうるもの |
|---|---|---|
| RTOS | 関所、QMI の印（MPU のフォールトで眠らせる）、シグナル（PendSV で枠を積む・SVC で戻る）、`mb_sleep_us` の戻り値 | すべてのタスクの切り替え・待ち・USB・ファイル・音・LAN |
| 表示 | 取得の待たせを関所 + MPU に、リングを 2 つに分けた | underrun・fifo_stall・作り直し、取得の間の他のタスク |
| メモリ | ローレゾ面の開き方（3 段）、FAT の受け場 1KB、LAN の受け場を上の端に、実行中はファイラーの一覧を読み直さない | モード 3〜6 が開けるか、ファイル操作、ファイラーの一覧 |
| ローレゾ | マップ 16 ビット、ABI 3.0 | Ruby・Python・SGX の BG の絵 |
| 速さ | mruby `-O2` + 関数の並び、MicroPython の並び | 速さ、フラッシュの大きさ |
| ファイラー | 一覧の扱い、RBRUN の引数 | 一覧・コピー・移動・ZMODEM・遠隔コマンド |

## 2. 先に作る道具（これが無いと実機の結果が信用できない）

1. **書き込んだ ELF で番地を引く**: 試しのあいだに組み直すと別の版の番地を読んでいた。書き込んだ版の写しを保存し、すべての台本がそれを使う
2. **書き先をドライブの中身で見つける**: 各試験用ドライブの頭に目印のファイル（例 `SGTEST.ID`、中身は「HDD-FAT」など）を置き、文字ではなく目印で探す（今日は A:〜H: のあいだで文字が動いた）
3. **再起動と止まった記録を必ず見る**: 各試しの前後でフレームの数（戻ったら再起動）と `crash_last` を読み、結果に添える
4. **観測の負荷を分ける**: SWD で SRAM を大量に読む・カウンタだけ読む・何も読まない、の 3 段を台本の選択肢に（USB のタスクの落ちは大量に読むときだけ出た）
5. **1 本で回せる入口 `scripts/devtest.sh`**: 段ごとに回して、合否・時間・カウンタ・再起動・止まった記録の表を 1 枚出す

## 3. 試験の段

### 段 A: ホスト（変更のたびに、約 15 分、自動）
- `scripts/test_all.sh` を全部（いまの 32 本と、RTOS の場面 21〜23・QEMU の 9）
- 足すもの:
  - **A1. コア 1 の模擬にシグナルと関所を混ぜる**（`scripts/host_rtos/test_tasks.c`）: 関所の開け閉め（取得のつもり）と各タスクへのシグナル（USR1・STOP/CONT・TERM）を乱数の間合いで。
    アプリのループの止まり・飢え・持ったまま眠る・`usb_lock` を持ったまま終わる、を見る
  - **A2. QEMU に MPU と MemManage を入れる**: QEMU の Cortex-M33 で MPU を本当に入れ、関所を閉じる -> 触ったタスクが眠る -> 開いたらやり直す、を本物の例外で（いまは模擬器だけ）
  - **A3. シグナルの乱打**: 計算・待ち・ミューテックスを持つタスクに割り込みから数万回送り、レジスタ・DCP・待ちの戻り値が崩れないか

### 段 B: 実機の機能（主な変更のあと、約 1.5 時間、ほぼ自動）

| 番号 | 中身 | 合格 |
|---|---|---|
| B1 | 見本 .rb・.py・.sgx の全部（mode0〜7・jumps・shogi・raster・hat・m640・mandel・tablet・sound・Doom の起動・TRACKER・sgbasic） | 例外なし、絵の色あり、underrun 0・作り直し 0、再起動 0 |
| B2 | ファイル: FAT・exFAT・NTFS・S: で作る・書く・読む・名前を変える・消す・フォルダ（Ruby の `fs_compat.rb`、遠隔コマンド） | CRuby と一致・中身一致 |
| B3 | ファイラー: 一覧・コピー・移動（複数・フォルダごと）・ZMODEM（4MB 超も）・エディタ・PNG・SMF・CD の再生とスペクトログラム | 中身一致、表示の乱れなし |
| B4 | USB 機器: キーボード・マウス・パッド・タブレット・MO・LS-120・FDD・CD・LAN（DHCP・NTP・TLS） | 認識・入力・読み書き |
| B5 | 速さの基準: HAT・M640・MANDEL（rb・py・sgx）、HDD の読み、バスの取り合い、負荷試験の限界 | 2026-10-31 の値から ±5% 以内 |

### 段 C: 実機の負荷と長時間（夜間など、数時間、自動）

| 番号 | 中身 | 合格 |
|---|---|---|
| C1 | 負荷試験 `scripts/stress_sgx.sh` を FAT・USB メモリで各 10 回 | すべて PASS |
| C2 | 走らせる・止めるのくり返し: Ruby -> Python -> SGX -> ファイラーを 200 回 | 再起動 0・一覧が止まらない |
| C3 | C2 を、SWD で SRAM を大量に読みながら | 落ちたら止まった記録を取り、原因を直すまで残す |
| C4 | 1 時間の連続: CD の再生 + LAN（ping・TLS）+ 負荷試験を交互に | underrun・作り直し・再起動 0、音が途切れない |
| C5 | ESC・Shift+ESC で途中で止める（読み書きの最中・描画の最中）を 100 回 | 後片づけされる（ファイラーへ戻る・メモリが減らない） |

### 段 D: 壊れ方の試し（手作業を含む、約 1 時間）

| 番号 | 中身 | 合格 |
|---|---|---|
| D1 | 読み書きの最中に USB の機器を抜く・挿す（HDD・USB メモリ・ハブ） | 本体が再起動しない・ファイラーが戻る |
| D2 | ウォッチドッグ（`W`）・`PANICTEST` で止まった記録が残るか | 次の起動で出る |
| D3 | 遠隔コマンドからタスクへシグナルを送る（`RSIG タスク 番号` を足す） | 既定の動きどおり（STOP で止まり CONT で戻る、TERM で終わる） |
| D4 | SRAM の空きを極端に減らした状態で各モードを開く（試し用にアリーナを詰める口を足す） | 開けないときは理由を出して断り、壊れない |

## 4. 既に見つかっている問題と、捕まえる試験

| 問題 | 捕まえる試験 |
|---|---|
| SWD で大量に読みながら Ruby -> Python で USB のタスクが落ちる（`usbfat` の `w_list_add`・TinyUSB の `msc_host.c` 338） | C3（再現させて止まった記録を取る）・A1 |
| ファイラーの一覧が「読み込み中」のまま止まる（完了の知らせが届かない） | C2・C5 |
| モード 3 では exFAT・NTFS を開けない（SRAM） | B2 で「断る」ことを確かめる |
| LAN を動かしたままモード 3 で読み書きできない | C1 は LAN を止める形のまま、別に「断る」ことを確かめる |

## 5. 進め方
1. 道具（2 章）: 約半日

3. 段 B: 約 1.5 時間 x 回すたび。初回で出た問題を直す
4. 段 C: 夜間に回せる形に
