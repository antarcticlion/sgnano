## 1. ハードウェア

| 項目 | 制約・注意 |
|---|---|
| ボード | WeAct Studio RP2350B Core Board。C ボード（PT8211 x4、GPIO A0〜A7、MIDI、ADC）を標準とする。P ボードも動くが DDC は無効 |
| PSRAM | 8MB を **151.2MHz** で使う。定格 133MHz を超える。常温の実機では安定しているが、個体差・温度で不安定になる可能性がある |
| 起動 | リセット直後にごくまれに起動しないことがある（GP0 がブート ROM にプルダウンされるため）。**A2 ステッピングの RP2350B で見られた問題で、A4 では出ていない**。そのときはリセットし直す。根本対策は基板の GP0 の 10kΩ プルアップ（C ボードは A4 なので未実装） |
| フラッシュ | 16MB。前半 8MB がファーム、`0x800000` から 4MB が S:、`0xC00000` から 4MB がフォント ROM |
| 音 | PT8211 は **4 声**。6 声にはしない（C ボードのピン配置と SRAM の都合） |
| 画面 | R・G・B 各 5 ビットの R-2R ラダー DAC。15kHz / 24kHz / 31kHz の 12 タイミング。モニタによっては 15kHz を受け付けない |
| DDC / EDID | 新しい基板（C ボード）では DDC を無効にしている。モニタの EDID は読まない。タイミングは手動で選ぶ |
| RTC | ハードの時計は無い。NTP で合わせる。電池が無いのでリセットで消える |
| USB | **ホスト専用**。USB デバイス（PC から見える機器）にはならない |
| GPIO | C ボードの GP34〜41 がユーザー用（A0〜A7）。PIO2 を開放。汎用の I2C / SPI / PWM / UART と GPIO 割り込みは未対応 |
| MIDI | C ボードの DIN MIDI（UART1 GP42/43）と USB MIDI ホスト |
| ADC | C ボードは GP46/47（専用 L/R）と GP40/41（A6/A7）。P ボードは GP40/41 |

## 2. ソフトウェア

### 2.1 全体

- ファイラー、テキストエディタ、IME、シェル sgsh、mruby / MicroPython / SG BASIC、SGX、M33BEATOS を載せている。
- 画面モードは 0〜7。モード 7 はテキスト 25 行 + 320x200x8 のビットマップ。
- **S: は 4MB の FAT12**。exFAT / NTFS は USB ストレージ側だけ。S: には大きなファイルを置けない。
- **S: の設定・ファイルは、前半 8MB の UF2（ファームのみ）では消えない。全体 16MB の UF2 では消える。**
- 画面の言語は 62 言語（2026-11-17 に EU・欧州・境の 34 言語を追加。`nn`・`rm` は重い地域言語として保留）。**日本語と英語以外は人が確かめていない仮訳**。
- **IME の辞書は別配布**（`sgnano-alpha1-2026.11-ime-dict.zip`、8.8MiB）。S: には入らないので、USB のドライブのルートに `SgnanoIME/sgnanoime.dic` として置く（つないだドライブを全部探す）。**辞書が無いと、日本語はかな入力だけ**（漢字に変換できない）。English・한국어 の入力は辞書が無くても使える。
- フォントは EmbFont16 v2.0（Uni、57,404 文字）。**v1 の ROM とは互換性が無い**。

### 2.2 言語

| 言語 | 制約 |
|---|---|
| mruby 4.0.0 | `require` / `load` / `require_relative`、`File` / `Dir` / `IO` / `Errno`、`Machine`、`Sound`、`MIDI`、`GPIO` / `PIO2`、`ADC` など |
| MicroPython 1.29.0 | `machine`、`os`、`fft`、`socket`、`json`、`hashlib`、`open()` など。float は倍精度（DCP） |
| SG BASIC | Microsoft BASIC 6502 の C 移植。R03.001。`.bas` / `.sgb` |
| 共通 | 3 言語の `Machine` は同じメソッドを持つ。違いは `docs/machine_api.md` |
| 制約 | 言語を走らせている間は画面モード 1 で始まる。ESC で止める。大きなファイルを同時に開くと PSRAM が足りないことがある |

### 2.3 SGX（外部実行ファイル）

- **ABI 5.x を凍結**。既存の関数・構造体・意味は α版の間に変えない。追加は末尾だけ。
- ファームは **4.x / 5.x** のプログラムを読み込む。**3.x 以前の扱いは確認中**（コードは 4.x と 5.x だけを受け付け、
  文書は 3.x も読むと書いている）。**2.x 以前は読み込まない**。
- 5.10 で組んだプログラムは α1 のファームで動く。α1 のファームで組んだプログラムは、
  5.10 以前のファームでは「新しいファームが要る」と断られることがある。
- SGX のロード上限は 4MB。PSRAM の空きによっては、それより小さい像でも載らないことがある。
- プログラムからファームの内部（RTOS のタスク、USB、ファイルシステムの下回り）に直接触らない。
  ABI の関数だけを使う。

### 2.4 SGCALC のマクロ

- セルの先頭が `#!ruby` / `#!python` / `#!basic` のテキストセルがマクロの見出し。
- マクロは **明示的に実行したときだけ** 動く。ファイルを開いただけでは実行しない。
- 実行方法は `Macro` メニューの `Run current` / `Run selection` / `Run all` / `Last error`。
- ソースの上限は **32KB / 512 行**。セルの入力は 1024 バイト、値の文字列は 255 バイトまで。
- **Undo は無い。** マクロが途中で失敗しても、そこまでの変更は残る。
- マクロからファイル・画面・`Machine` をどこまで使えるかは、言語と実行の形による。
  v1 は `Sheet` と計算を基本にする。信頼できないシートのマクロを実行しない。
- マクロの `print` は画面に出さない（UART のログに出る）。言語の `exit` / `END` はマクロだけを終わらせる。
- 数式の誤りは `#DIV/0!` などの文字列で返る。引数の誤りは例外になる。

### 2.5 音

- PT8211 は 4 声。VGM のチップ数が多い曲は、声が足りない・SRAM が足りないことがある。
- MP3 / OGG / WAV は 96kHz / 24bit まで再生できる（PT8211 は 16bit なので上位 16bit で出力）。
- VGM / VGZ の再生は、曲のチップによって負荷が高い。Power Drift 72%・Darius 54% などの実測がある。
- ~~VGZ → WAV / MP3 の変換は、大きい曲でメモリ不足になる~~【2026-11-16 直した】PSRAM に入らない曲は、丸ごと持たずにファイルからページで引いて書き出す（256MB まで）。`.vgz` は書き出し先のフォルダに作業ファイル（`~vgmwork.vgm`）を作って展開し、終わったら消すので、**その分の空きが要る**。丸ごと持てる曲より 2 倍ほど遅い（展開 6.7MB・254 秒の曲の MP3 が約 23 分）。
- **PSRAM に入らない大きい VGZ も再生できるが、ファイルから読みながら鳴らすので途切れが多く、聴ける音にならない**。大きい曲は MP3 に書き出して聴く。
- 音楽 CD の再生中は、ほかの音を同時に鳴らさない（ストリームが排他）。
- 音源の診断キー（`A` / `C` など）は開発用。普段は使わない。
- **サウンドフォント（SF2）は配布物に入れていません。** ファームの SMF 再生（`Sound.play` / mplay）は**内蔵の 4 声ウェーブテーブル**で鳴らすので、SF2 は要りません。SF2 が要るのは **`smf2vgm.sgx`**（MIDI → VGM / VGZ の変換）だけです。
  - 置き場: `<ドライブ>:/SoundFonts/`（`MuseScore_General_Full.sf2` を優先し、無ければ最初の `.sf2`）。`--sf2 FILE` でも指定できます。
  - ダウンロード: [MuseScore_General.sf2](https://ftp.osuosl.org/pub/musescore/soundfont/MuseScore_General/MuseScore_General.sf2)（MuseScore General、MIT。約 83MB）。S: の 4MB には入りません。
  - 変換した VGM / VGZ を配るときは、MuseScore General の著作権表示と MIT の許諾文を添えてください。

### 2.6 USB・ストレージ

- USB ハブの先の機器の抜き差しで、キーボードやタブレットが一時的に消えることがある（#51）。
  推奨はセルフパワーのハブ（`2109:2817`、VL817）。F8 の EP 一覧で状態を見る。
- 速い抜き差し、同じポートへの別機器の接続、ハブの先のロースピード機器で不安定になることがある。
- USB メモリ・HDD・FDD・CD・MO・LS-120 のすべてを同時に保証しない。エンドポイントは 15 本の上限。
- ~~JOIN（分割ファイルの結合）は 64 個まで~~【2026-11-16 直した】999 個まで。超えると断る（以前は黙って 64 個で止めていた）。
  `scripts/zm.py` はつないだ数を照らし合わせ、違えば部品を消さない。
- **【2026-11-18 修正（α2）】**同じ exFAT / NTFS の中の 4MB 級（PSRAM に入らない大きさ）の COPY は、
  置き場の一覧を先に取り、書き込みの隙間で元のセクタを直読みして流す（side）ようにしました。
  8.3MB のコピーを 3 回、4MB 級を含めて読み戻しの CRC32 一致で確認しました（2026-11-18）。
- 大きなファイルの ZMODEM 転送は遅い。4MB を超えるファイルは分割して送る。
- **【2026-11-18 修正（α2）】**SRAM の空きが細かいとき（exFAT / NTFS のドライブをつないだときなど）、
  一覧が 256 件に落ちることがありました。名前の置き場を PSRAM へ移し、512 件・名前 8KB のまま出るように
  しました。

### 2.7 画面・テキスト

- テキスト面は 80x30（24kHz では 80x25）。モード 7 は 25 行。
- テキストの属性は 32 ビット（色反転・ブリンク・線・ボールド・回転・倍角）。
- モード 1〜5・7 は 640 幅。15kHz ではモード 1〜5・7 を開けない（0 と 6 だけ）。
- モード 3〜5 でローレゾ面を開くと、SRAM の空きによって VGM を同時に鳴らせないことがある。
  16KB のローレゾ面で足りるプログラムは `SGX_MODE_LR_SMALL` を使う。
- 画面モードの切り替えで、モニタが数秒ブラックアウトすることがある（31kHz の 5↔6）。

### 2.7b 圧縮と書庫（2026-11-17）

- 扱う形: gzip・zlib・deflate・bzip2・LZMA（.lzma）・xz、ZIP（無圧縮・deflate・bzip2・LZMA）・7z・tar（.tar.gz / .tar.bz2 / .tar.xz / .tar.lzma）。
- 作業場は PSRAM。空きに入らなければ圧縮の段を下げる（LZMA・xz は空き 3MB で段 0、辞書 64KB）。展開の辞書は中身の大きさまで縮めるので、PC の既定の 7z・xz も中身が入れば展開できる。
- **ふつうの空きで足りないときは FB の 4 ページを作業場に借りる**（FB を出していないときだけ）。借りたページは返すときに 0 で消すので、画面モード 1 などで前に FB に描いた中身は、圧縮・展開の口を呼ぶと消える。
- 出力が PSRAM に入らない大きさだと、大きさを数えるために 2 回圧縮する（時間が 2 倍）。4GB を越える出力は作らない。S: へは PSRAM に入る大きさだけ。
- 7z を作るのは LZMA のソリッド 1 ブロックだけ（LZMA2・BCJ では作らない）。7z の BZip2・Deflate の方式は読まない。BCJ などのフィルタつきの 7z はブロック全体を PSRAM に置くので、大きいと展開できない。
- ZIP の暗号・Deflate64・Zstandard は扱わない。xz の展開は 1 つの塊の大きさが PSRAM に入るものだけ（辞書を縮められない形もある）。

### 2.8 キーと画面の写し（2026-11-17 判明）

- **【2026-11-18 修正】**一覧の `Shift+F1`〜`Shift+F12` は `alpha1-2026.11.1` で直りました（α1 では効きませんでした。
  原因は `list_key()` が受け取るキーの形の食い違い）。
- **【2026-11-18 修正（α2）】**MicroPython の見本の `fontdemo.py` が実機で動かなかった件は、`W = M.text_cols` を
  `M.text_cols()` に直して解決した（API はメソッド）。`gfx.py` は**転送の途中で切れたファイル**が原因で、
  完全なファイルなら `gfx: all ok` で通る。
- **画面の写しは `Alt+PrintScreen`**（または `Alt+F5`）。**【2026-11-18 修正（α2）】**α1 では `Alt+F5` が一覧でしか効きませんでしたが、いまはビュアー・エディタの上でも効きます。
- **写しには PSRAM の連続した空き（約 614KB + 作業域）が要ります。**
  **【2026-11-18 修正（α2）】**ビュアーの索引はファイルの行数に合わせて取るようにしました（以前は 29 バイトの
  ファイルでも索引 2MB + 色分け 512KB を取り、写しが入りませんでした）。大きいファイルを開いているときや、
  exFAT / NTFS のドライブのキャッシュが PSRAM を使っているときは、まだ `no memory` で撮れないことがあります
  （`Alt+PrintScreen` でも同じ）。
- **Ruby / Python / SGX の実行中は画面を写せません**（写しはファイラーのアプリ時間で組み立てるため）。
  **【2026-11-18 修正（α2）】**押すと「not while a program runs」と出るだけで、キーは効きます
  （α1 では写しが終わらず、キーが効かなくなったように見えました）。

### 2.9 フォント

- **v2 のファームに v1 のフォント ROM を付けると、文字が出ない。** 逆も同じ。
- 全体 UF2 はフォント ROM を上書きする。前半 UF2 はフォント ROM を消さない。
- フォントを差し替えるときは、ファーム・S:・フォント ROM の組み合わせをリリースノートで確認する。
- 旧 `EmbUniFontUni.uf2` は α1 では使わない。

## 3. 書き込みと更新

### 3.1 UF2 の種類

| UF2 | 何が入る | 向いている場面 |
|---|---|---|
| 全体（16MB） | ファーム + S: の初期値 + フォント ROM | 初回、または初期状態に戻す。**S: は消える** |
| 前半（8MB） | ファームのみ | ファームだけ更新する。**S: とフォントは残る** |
| 後半（8MB） | S: の初期値 + フォント ROM | S: とフォントを入れ直す。**ファームは残る** |
| S: のみ（4MB、任意） | S: の初期値 | S: だけ初期化する |
| フォントのみ（4MB、任意） | フォント ROM | フォントだけ入れ替える |

### 3.2 手順

1. ボードの BOOTSEL を押しながらリセットし、`RPI-RP2` ドライブを出す。
2. 必要な UF2 をコピーする。
3. コピーが終わったらリセットする。
4. 起動バナー、ファイラー、S: の中身、画面の文字を確認する。

- **初回は全体 UF2** を使う。S: とフォントが一度に入る。
- **ファームだけ更新するときは前半 UF2**。S: の設定・ファイル・セーブは残る。
- 全体 UF2 を書く前に、S: の必要なファイルを USB メモリへコピーする。
- 書き込み中に電源を切らない。USB ケーブルは給電能力のあるものを使う。
- SWD で書き込むと、フラッシュ全体の消去をしない限りフォント ROM は残る。

### 3.3 起動しないとき

1. リセットする。GP0 の既知の問題なら、これで起動することがある。
2. 電源を入れ直す。USB ハブを外して本体に直結する。
3. 全体 UF2 を書き直す。それでもだめなら SWD で書き込む。
4. QSPI が中途半端な状態なら `scripts/flash_swd.sh --rescue` を使う（開発者向け）。
5. 起動ログ（UART 921600）と、次の起動の `[boot] ** the previous boot stopped` を確認する。

## 4. データ

- S: は 4MB。設定・言語ファイル・小さなプログラムに向く。大きなファイルは USB ストレージへ。
- 全体 UF2 を書くと S: は初期化される。**バックアップは USB メモリへコピーする。**
- 前半 UF2 は S: を消さないが、ファームの不具合で S: が壊れる可能性はゼロではない。
  大切なデータは S: に置かない。
- Doom のセーブは WAD のフォルダの `.savegame/`。S: には入らない。
- ファイルの属性・日時は FAT / exFAT / NTFS で扱う。読み出し専用の扱いはドライブによって違う。
