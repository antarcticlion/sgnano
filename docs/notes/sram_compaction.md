# SRAM アリーナのコンパクション

## 目的

`src/mem/vmem.c` の SRAM アリーナを協調的に詰め、**大きな連続空き**を作る。
言語のヒープは PSRAM なので、ここで大きな連続領域が要るのは主に次の用途:

- ローレゾ面・ビットマップ面・一時的なファイルの受け場
- SGX のバックバッファ・タスクの SRAM スタック
- ファイラーや ZMODEM の作業場

## 前提と制約

- `vmem_alloc()` は**生ポインタ**を返す。移動するには、所有者が持っているポインタを
  すべて更新する必要がある。汎用的なポインタ追跡はできない。
- タスクはフラッシュまたは PSRAM に乗っている。コンパクションの開始は**共有の状態**で
  知らせ、各タスクが安全点で `vmem_compact_point()` を呼んで ack する。信号は使わない
  （2026-11-03、PSRAM スタックのファイラーで信号の復帰が HardFault になったため）。
- 表示・DMA・割り込みが触っているブロックは**動かさない**（pinned）。
- コンパクションはアプリ時間の側（core0 の冷たい経路）で行う。core1 の描画と同時に
  SRAM を動かさない。
- 言語のタスクは PSRAM のスタックを持つが、SRAM の一時ブロック（rbfs の読み出し、
  sysdisk のブロック、fsplit のチャンクなど）を持つことがある。**いまはファイラーの
  一覧の 3 ブロックだけ**を可動として登録している。

## API（`src/mem/vmem.h`）

```c
// 移動できるブロックを登録する。moved は新しい番地で呼ばれる。
// user は所有者の構造体（ポインタを更新するために使う）。
typedef void (*vmem_moved_fn)(void *new_p, void *user);
bool vmem_move_register(void *p, vmem_moved_fn moved, void *user);
bool vmem_move_register_as(void *p, vmem_moved_fn moved, void *user, void *owner);
bool vmem_move_unregister(void *p);

// タスクの開始時に 1 回。このタスクを待ち手に加える。
void vmem_compact_task_init(void);
// 安全点で呼ぶ。コンパクションが始まっていれば ack して、終わるまで眠る。
void vmem_compact_point(void);

// 大きな連続空きを作る。成功したら true。失敗したら予約を全部返す。
bool vmem_compact_request(size_t need);

// 状態（ログ・診断用）
typedef enum { VMEM_CMP_IDLE, VMEM_CMP_WAIT, VMEM_CMP_MOVE, VMEM_CMP_DONE, VMEM_CMP_ABORT } vmem_cmp_state_t;
vmem_cmp_state_t vmem_compact_state(void);
```

## 動き

1. **要求**: `vmem_compact_request(need)` は、すでに `need` の連続空きがあれば
   何もせず true を返す。なければコンパクション専用のタスク（優先度 6、PSRAM の
   4KB スタック。一度だけ作る）を起こし、自分は待つ。待つ間は弱い口
   `vmem_compact_pump()` を呼ぶ。アプリのタスクでは、これがファイラーを 1 フレーム
   進める（ファイラーはセマフォで動くタスクなので、待ち手として安全点へ来させる）。
2. **予約**: コンパクタは、すべての空き区画に `VMEM_SEG_COMPACT` を立てる。
   `vmem_alloc()` と `alloc_fixed()` はこの区画から配らない。動かす最大ブロックの
   大きさで PSRAM の bounce buffer を取る。取れなければ中止する（SRAM を削らない）。
3. **開始**: 状態を `WAIT` にし、待ち手の `acked` を下ろす。**呼び手とコンパクタ自身は
   数えない**（呼び手はまだ自分のポインタを使っている。呼び手のブロックは、呼び手が
   安全だと約束した `vmem_compact_request_here()` のときだけ動かす）。
4. **停止**: 各タスクは安全点で `vmem_compact_point()` を呼ぶ。`WAIT` / `MOVE` なら
   `acked++` して、終わるまで 1ms ずつ眠る。アプリは `loop_once()` の先頭と
   `filer_task_app_time()` の待ちの合間、ファイラーはループの先頭とセマフォの待ちの
   あとで見る。呼び手がアプリのときは、待つ間にファイラーを pump して安全点へ来させる。
   コンパクタは 300ms 待ち、揃わなければ中止する。
5. **移動**: 全員が止まったら、空き F の隣の**可動ブロックの列**を F へ 1 個ずつ移す。
   列の向こう側に別の空き G があれば、最後に F と G が 1 つに合わさる。
   - 動かすたびに、空いたブロックの所が F に加わるので、F の大きさはその都度 F の
     まま。列の各ブロックが F に収まれば、列全体を移せる。
   - `dst` と `src` が重なる場合は bounce buffer 経由、重ならなければ `memmove`。
   - 移動後、所有者の `moved(new_p, user)` を呼ぶ。所有者は保存しているポインタを
     すべて新しい番地へ直す（いまはファイラーの `fl.lst.ents` / `pool` / `order` と
     `appmem` の記録）。
   - 古い区画を返し、隣の空きと結合する。結合しても予約の印は残す。
6. **完了**: 予約と bounce を返し、`state = DONE` にしてタスクを起こす。呼び手は
   `vmem_free_largest()` を確かめてから、目的の確保をやり直す。

## 移動の計画（`compact_plan_find` / `compact_plan_run`）

- 区画の表を走査し、空き F の左右それぞれについて、隣から続く可動ブロックの列を
  数える。列の先に別の空き G があり、列の各ブロックが F に収まるなら、
  `potential = F + G` の計画になる。
- いちばん `potential` の大きい計画を選び、列を F へ 1 個ずつ移す。移すたびに
  空き区画の位置が列の側へ動くので、その都度、区画を引き直す。
- 合計の移動数が `VMEM_CMP_STEPS`（64）を超えたら止める。計画が無ければ中止。
- 1 個だけの列（空き・ブロック・空き）も同じ仕組みで扱える。

## 所有者（タスク）側の決まり

- `vmem_move_register()` は**そのブロックを持つタスク**から呼ぶ。登録したタスクが
  待ち手になる。`vmem_move_register_as()` は持ち主を明示する。ファイラーの一覧は
  アプリ（監督）のタスクを持ち主にしている（`app_task_handle()`）。ファイラーが言語の
  ために終わっても登録が残り、言語のタスクから画面モードを変えるときに一覧を動かせる。
  `vmem_move_unregister()` で外す。タスクが終わったときは `mb_kernel.c` の
  `detach()` が弱い口 `vmem_move_clear_task()` を呼び、そのタスクが持ち主の登録と
  待ち手を消す。
- 安全点は、そのタスクが移動対象の SRAM ポインタをローカルに持っていない場所:
  - ファイラー: ループの先頭と `filer_run` のセマフォを受けた直後（`ftask.c`）
  - アプリ: `loop_once(false)` の先頭と `filer_task_app_time()` の待ちの合間（`main.c` /
    `ftask.c`）。一覧の並べ替えなどはその前。
  - 言語・シェル: まだ登録するブロックが無いので、いまは待ち手にしていない。
- `moved()` の中では確保・解放・眠りをしない。ポインタと、そこから派生した番地を
  直すだけにする。
- コンパクション中は新しい SRAM の確保を控える。予約した区画は `vmem_alloc()` が
  避けるので、他のタスクが確保を続けても宛先は減らない。

## 表示の VRAM を作り直す（`screen_compact_rebuild(target, need)`）

大きな面（テキスト・ローレゾ・320x200x8 ビットマップ）を開くときに SRAM が
足りなければ、`screen_set_mode()` は次の順で作り直す:

1. 画面モード 0（同期は出したまま）にして、テキスト・ローレゾ・ビットマップの面を閉じる。
2. `need` は、開き直す面の大きさに、目的のモードがテキスト面を使うならテキスト面
   （約 53KB、余裕を見て 56KB で見積もる）を足したもの。テキスト面の失敗なら 56KB、
   ビットマップなら 64KB + テキスト、ローレゾなら `lr_need_bytes()` + 4KB + テキスト（56KB）。
3. `vmem_compact_request(need)` を呼ぶ。
4. モードは戻さず、呼び手が目的の面をもう一度開く。大きな面を先に開き、そのあと
   テキスト面を開き直す（モード 7 など）。成功すれば、そのまま目的のモードを作る。
   失敗したら、元のモードへ戻してエラーを返す。

表示は一瞬消える（ユーザー了承済み）。面の中身は消えるので、呼び手が描き直す。
一覧の持ち主はアプリのタスクなので、ファイラーが呼び手でも一覧は動かせる。

## 制約・これから

- いま可動として登録しているのはファイラーの一覧の 3 ブロックだけ。表示 VRAM・
  DMA・割り込みが触るブロックは pinned のまま。言語の一時ブロック（rbfs /
  sysdisk / fsplit）を可動にするのは次段。
- Ruby・Python・シェルは、言語を始める前に一覧と下書きを返す（`filer_release_sram`）。
  大きな面のための空きを先に作り、コンパクションはその空きの断片をまとめるために使う。
- 呼び手のブロックは動かさない（呼び手が安全点にいる保証が無いため）。一覧の持ち主は
  アプリのタスクなので、ファイラー自身が `screen_set_mode()` を呼ぶ場合も、アプリが
  安全点で止まって一覧を動かせる。
- コンパクションのコード（`src/mem/vmem.c`）はフラッシュに置く（`ld/placement.cmake` の
  `SGNANO_FLASH_FILES`）。アリーナが一覧とテキスト面で埋まりやすいので、コードで SRAM を
  削らないため（実機でアリーナの空きが約 147KB -> 155KB になった）。
- コンパクションの時間は予測しにくい。要求は「大きな空きが要る」ときだけにし、
  通常の確保では発動しない。
